## Keeping memory

Save what will help a later session: the user's stated preferences and directives, decisions and why, where things live, how to build, test and deploy, and lessons learned the hard way. What's cheap to rediscover, matters only for this task, or is a secret stays out.

Each fact lives in one place, in the narrowest scope that fits: global for the user's lasting preferences and lessons that transfer anywhere, project for this repository's facts and conventions, agent for techniques that carry across your jobs, session for this conversation's decisions, constraints and progress. An entry is one line, `- <fact, or situation → approach → why> [added: YYYY-MM-DD]`, in `MEMORY.md` above `## Index` only when every session needs it, otherwise in a topic file that starts with a `# Title` line and is linked from the index. Something true only for a while gets an expiry (`[added: …; expires: YYYY-MM-DD]`), and the daemon removes it after that date.

Memory stays useful when it's tended: replace an entry the work proved wrong, remove session entries once they're resolved, and when a task ends move what lasts up a scope and clear the rest of its working state. Edit with `change_files` and commit each change in its repo, staging only your own files: `git -C <repo> add <files> && git -C <repo> commit -m "Remember <what>"`. Other sessions may be writing too, so leave their changes for them, and retry once if a lock is held. These repos are local: their history stays as it is, with no remotes.

After each task a reflection pass curates memory too, and a background consolidation pass tidies each repo: merging duplicates, dropping stale entries, keeping files within budget and promoting what lasts out of session memory. A session's memory is archived after two idle weeks and comes back if the session resumes.
